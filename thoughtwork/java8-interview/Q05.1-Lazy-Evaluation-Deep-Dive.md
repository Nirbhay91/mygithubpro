# Q5.1 — Lazy Evaluation in Java 8 Stream API

## 2-Minute Interview Answer

Lazy evaluation means that intermediate Stream operations are not executed immediately when they are defined. They are executed when a terminal operation is invoked.

Operations such as `filter()`, `map()`, and `sorted()` are intermediate operations. They build the Stream pipeline and generally do not process source elements immediately. A terminal operation such as `collect()`, `count()`, `forEach()`, `reduce()`, or `findFirst()` triggers execution.

Lazy evaluation also enables efficient pipeline processing and works with short-circuiting operations such as `findFirst()`, `findAny()`, `anyMatch()`, `allMatch()`, `noneMatch()`, and `limit()` so unnecessary elements may not be processed.

## Example

```java
List<Integer> numbers = Arrays.asList(10, 20, 30, 40);

Stream<Integer> stream = numbers.stream()
        .filter(n -> {
            System.out.println("Filtering: " + n);
            return n > 20;
        });

System.out.println("Stream created");
```

The filtering logic does not execute merely because `filter()` was declared. The pipeline is evaluated when a terminal operation is added:

```java
List<Integer> result = numbers.stream()
        .filter(n -> {
            System.out.println("Filtering: " + n);
            return n > 20;
        })
        .collect(Collectors.toList());
```

## Lazy Evaluation vs Short-Circuiting

These are related but different concepts.

- **Lazy evaluation:** delays intermediate-operation processing until a terminal operation triggers the pipeline.
- **Short-circuiting:** allows processing to stop once the terminal operation has enough information to determine its result.

Example:

```java
Optional<Integer> result = numbers.stream()
        .filter(n -> n > 10)
        .findFirst();
```

Conceptually, processing can stop as soon as the first matching element is found.

## Stream Pipeline

```text
Source
  ↓
stream()
  ↓
filter()  ← intermediate / lazy
  ↓
map()     ← intermediate / lazy
  ↓
filter()  ← intermediate / lazy
  ↓
findFirst() ← terminal / triggers execution
  ↓
Result
```

## Why Lazy Evaluation?

1. Avoids unnecessary work.
2. Enables pipeline optimization.
3. Works naturally with short-circuiting operations.
4. Allows element processing through multiple stages without requiring a separate materialized collection after every intermediate stage.

## Important Interview Traps

### Does `filter()` execute immediately?

No. `filter()` is an intermediate operation. It contributes to the pipeline; actual processing is triggered by a terminal operation.

### Is lazy evaluation the same as short-circuiting?

No. Lazy evaluation is about **when execution starts**. Short-circuiting is about **when processing can stop**.

### Does lazy mean nothing happens when the pipeline is created?

No. The Stream pipeline and its operation structure are created. What is deferred is the normal traversal/processing of source elements.

## Real Project Example — Enterprise Claim System

Suppose we need the first approved high-value claim:

```java
Optional<Claim> claim = claims.stream()
        .filter(c -> c.getStatus() == APPROVED)
        .filter(c -> c.getAmount().compareTo(BigDecimal.valueOf(100000)) > 0)
        .findFirst();
```

The stream can process claims through the pipeline and stop once `findFirst()` obtains the required result.

## 30-Second Answer

> Lazy evaluation in Stream API means intermediate operations like `filter()` and `map()` are not executed immediately. They build the stream pipeline. Actual processing starts when a terminal operation such as `collect()`, `count()`, or `findFirst()` is invoked. This enables efficient pipeline processing and, together with short-circuiting operations, can avoid processing unnecessary elements.

## Key Memory Point

**Intermediate operation → lazy → builds pipeline**  
**Terminal operation → triggers execution**  
**Short-circuiting → may stop execution early**

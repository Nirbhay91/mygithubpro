# Q5.4 — `filter()` vs `map()` in Java 8 Stream API

## 2-Minute Interview Answer

> `filter()` and `map()` are both intermediate Stream operations, but they solve different problems. `filter()` is used to select elements that satisfy a condition; it keeps the element type and may reduce the number of elements. `map()` is used to transform each element into another value; it normally keeps the number of elements the same while changing the element type or value.
>
> For example, in an enterprise claim system, I can use `filter()` to select only approved claims and `map()` to convert those claims into DTOs or extract their claim amounts. They can also be chained together: filter first, then transform the remaining elements with map.

## 1. `filter()` — Select Elements

`filter()` accepts a `Predicate<T>`:

```java
List<Integer> numbers = Arrays.asList(10, 15, 20, 25, 30);

List<Integer> result = numbers.stream()
        .filter(n -> n > 20)
        .collect(Collectors.toList());
```

Result:

```text
[25, 30]
```

The condition returns `true` or `false`:

```text
n > 20
   ↓
true  → keep element
false → discard element
```

### Key idea

> **filter = selection**

It does not transform an element into another value. It decides whether the element remains in the stream.

---

## 2. `map()` — Transform Elements

`map()` accepts a `Function<T, R>`:

```java
List<Integer> numbers = Arrays.asList(10, 20, 30);

List<Integer> result = numbers.stream()
        .map(n -> n * 2)
        .collect(Collectors.toList());
```

Result:

```text
[20, 40, 60]
```

Flow:

```text
10 → 20
20 → 40
30 → 60
```

### Key idea

> **map = transformation**

Each input element is transformed into an output value.

---

## 3. Core Difference

```text
filter()
T → T or removed
Condition decides whether element survives
```

```text
map()
T → R
Transforms every element that reaches it
```

| Feature | `filter()` | `map()` |
|---|---|---|
| Purpose | Select | Transform |
| Functional interface | `Predicate<T>` | `Function<T,R>` |
| Return from lambda | `boolean` | Output value `R` |
| Can reduce element count? | Yes | Normally no |
| Changes element type? | No | Yes |
| Example | Keep approved claims | Claim → ClaimDTO |

---

## 4. `filter()` Can Reduce the Number of Elements

Input:

```text
[10, 15, 20, 25, 30]
```

Code:

```java
.filter(n -> n > 20)
```

Output:

```text
[25, 30]
```

Five elements entered; two remained.

---

## 5. `map()` Normally Preserves the Number of Elements

Input:

```text
[10, 20, 30]
```

Code:

```java
.map(n -> n * 2)
```

Output:

```text
[20, 40, 60]
```

Three elements entered; three values came out.

The mapping function can return `null`, but that still represents an output element; `map()` itself does not filter it out.

---

## 6. `filter()` + `map()` Together ⭐

This is one of the most common interview patterns:

```java
List<String> result = names.stream()
        .filter(name -> name.startsWith("A"))
        .map(String::toUpperCase)
        .collect(Collectors.toList());
```

Flow:

```text
Names
  ↓
filter → select names starting with A
  ↓
map → convert to uppercase
  ↓
collect
```

For:

```text
[amit, rahul, ankit, rohit]
```

Result:

```text
[AMIT, ANKIT]
```

### Why filter first?

If transformation is expensive and the transformation isn't needed for rejected elements, filtering first can avoid unnecessary work.

For example:

```java
stream
    .filter(this::isApproved)
    .map(this::toDto)
```

Only approved claims are converted to DTOs.

## 7. Real Enterprise Claim System Example

Suppose:

```java
List<Claim> claims;
```

Requirement:

> Get DTOs only for approved claims.

```java
List<ClaimDTO> approvedClaims = claims.stream()
        .filter(claim -> claim.getStatus() == Status.APPROVED)
        .map(this::toClaimDTO)
        .collect(Collectors.toList());
```

Here:

```text
filter() → business-rule selection
map()    → domain object → DTO transformation
collect() → terminal operation
```

This is a clean example to use in a 5-year interview.

## 8. Another Example — Extract Data

Suppose we only need claim IDs from approved claims:

```java
List<Long> claimIds = claims.stream()
        .filter(claim -> claim.getStatus() == Status.APPROVED)
        .map(Claim::getId)
        .collect(Collectors.toList());
```

Type transformation:

```text
Claim
  ↓ filter
Claim
  ↓ map
Long
```

So `map()` can change the element type.

## 9. Common Interview Trap

### Question:

> Can `filter()` change the type of an element?

No.

`filter()` has the shape:

```text
Stream<T> → Stream<T>
```

The element is either retained or removed.

`map()` can change the type:

```text
Stream<T> → Stream<R>
```

Example:

```java
Stream<Claim> → Stream<ClaimDTO>
```

---

## 10. Another Trap — Does `map()` Filter Nulls?

No.

```java
List<String> result = names.stream()
        .map(name -> null)
        .collect(Collectors.toList());
```

The stream still contains mapped output elements (null values). If nulls need to be removed, use `filter(Objects::nonNull)` explicitly.

```java
List<String> result = names.stream()
        .map(this::convert)
        .filter(Objects::nonNull)
        .collect(Collectors.toList());
```

## 12. Lazy Evaluation Connection

Both are intermediate operations:

```java
claims.stream()
      .filter(...)
      .map(...)
      .collect(...);
```

`filter()` and `map()` do not normally process the source merely because they were declared. `collect()` is the terminal operation that triggers the pipeline.

This connects directly to **Q5.1 — Lazy Evaluation**.

---

## 13. Short-Circuiting Example

```java
Optional<ClaimDTO> result = claims.stream()
        .filter(claim -> claim.getStatus() == Status.APPROVED)
        .map(this::toClaimDTO)
        .findFirst();
```

`findFirst()` is terminal and short-circuiting. Once the required first result is found, processing can stop.

Conceptually:

```text
Claim 1 → filter → rejected
Claim 2 → filter → approved → map → DTO
                                      ↓
                                  findFirst
                                      ↓
                                    STOP
```

## 14. `filter()` vs `map()` vs `flatMap()`

| Operation | Main purpose | Example |
|---|---|---|
| `filter()` | Select | Keep approved claims |
| `map()` | Transform | Claim → ClaimDTO |
| `flatMap()` | Transform + flatten | Claim → multiple line items |

Memory trick:

```text
filter  → Which elements?
map     → What should each element become?
flatMap → What if each element produces multiple elements?
```

## 15. Interview Coding Question

### Question

Given:

```java
List<Integer> numbers =
        Arrays.asList(1, 2, 3, 4, 5, 6);
```

Return squares of even numbers.

### Answer

```java
List<Integer> result = numbers.stream()
        .filter(n -> n % 2 == 0)
        .map(n -> n * n)
        .collect(Collectors.toList());
```

Result:

```text
[4, 16, 36]
```

Execution conceptually:

```text
1 → filter ❌
2 → filter ✅ → map → 4
3 → filter ❌
4 → filter ✅ → map → 16
5 → filter ❌
6 → filter ✅ → map → 36
```

## 16. Senior-Level Interview Answer

> `filter()` and `map()` are both lazy intermediate operations, but their semantics are different. `filter()` uses a `Predicate` to decide whether an element should remain in the stream and therefore can reduce the number of elements, while `map()` uses a `Function` to transform each element from `T` to `R`. In a real application, I would typically filter according to a business condition first and then map the selected domain objects into DTOs or other required representations. This can also avoid doing unnecessary transformation work for elements that will ultimately be rejected.

## ⭐ Final Memory Rule

```text
filter()
→ selection
→ Predicate
→ boolean
→ can remove elements

map()
→ transformation
→ Function
→ T → R
→ normally one output per input
```

### 30-Second Answer

> `filter()` is used to select elements based on a condition and takes a `Predicate`, while `map()` transforms each element and takes a `Function`. `filter()` can reduce the number of elements, whereas `map()` normally preserves the count but can change the element type. For example, in a claim system, I can filter approved claims and then map them from `Claim` objects to `ClaimDTO` objects.
